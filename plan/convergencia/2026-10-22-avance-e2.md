## Hallazgos

### H-01 · En producción local no se puede iniciar sesión sin Caddy

- **Qué pasa:** con `npm run build && npm start`, el acceso personal responde «No se pudo completar la operación. Inténtelo de nuevo.» (500) para cualquier usuario.
- **Por qué:** en producción, `src/lib/ip.ts` › `obtenerIp()` solo acepta la cabecera `X-Real-IP`, que pone Caddy (decisión 29, RNF-15; JG-06 y CE-05). Sin Caddy delante no hay IP de confianza y la operación se rechaza. **Es el comportamiento esperado por seguridad**, no un error; solo choca con el guion del 19/10, que pedía `npm start` sin proxy.
- **Dueño:** Jordin (JG-06) y Carlos (CE-05). No se cambió código.
- **Alternativa:** para una demostración en un equipo, usar `npm run dev` (en desarrollo la IP es `127.0.0.1`). En producción (JG-19 y JG-22), Caddy la pone siempre.

### H-02 · En producción local no hay imágenes sin Cloudflare R2

- **Qué pasa:** con `npm start`, publicar una imagen en el panel falla y las imágenes de la semilla de demostración (`/api/imagenes/demo/…`) responden 404, así que el sitio se ve con imágenes rotas.
- **Por qué:** `ALMACENAMIENTO=disco` solo existe en desarrollo y en GitHub Actions (decisión 78); en producción `src/modulos/almacenamiento/servicio.ts` exige R2. R2 depende de las cuentas de INCOVSA (P-94), por lo que CE-08 está bloqueada.
- **Dueño:** Carlos (CE-08, bloqueada por P-94).
- **Alternativa:** `npm run dev` para una demostración local; en producción, cuando CE-08 configure R2.

### H-03 · `next start` avisa que no corresponde con `output: standalone`

- **Qué pasa:** al arrancar, Next.js avisa: «"next start" does not work with "output: standalone" configuration. Use "node .next/standalone/server.js" instead». Aun así, el servidor funcionó en todo el recorrido.
- **Por qué:** `output: 'standalone'` es para la imagen de Docker (JG-02 y CE-05), que arranca con `node server.js`.
- **Dueño:** ninguno; no afecta a producción. Solo se anota porque el guion del 19/10 indicaba `npm start`.

## Comandos para levantar la demostración en un equipo

Con PostgreSQL local y el `.env` completo (`plan/instalacion.md`). Por H-01 y H-02, la demostración local se levanta **en desarrollo**:

```
git switch develop
git pull --ff-only
npm ci
npm run db:reiniciar
npm run db:semilla
npm run semilla:demo
npm run dev
```

Después se abre `http://localhost:3000/acceso` y se usan las cuentas `ejemplo.01` (Gerencia), `ejemplo.03` (Facturación y sitio), `ejemplo.05` (Bodega) y `ejemplo.08` (panel del sitio), con la contraseña de `CLAVE_DEMO`. El archivo de Odoo está en `pruebas/fixtures/odoo/odoo-ejemplo-anonimizado.xlsx`.

`npm run db:reiniciar` borra la base local: solo se usa en la base de desarrollo.
